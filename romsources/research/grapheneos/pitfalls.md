# GrapheneOS install pitfalls

Install-specific snapshot checked 2026-10-16. These are documented prerequisites and risks, not results from flashing a device.

## Unlockability and carrier variants

- GrapheneOS warns that carrier-sold Pixels, primarily a US issue, may have OEM unlocking disabled by carrier-specific configuration stored in the device's persist partition. It recommends avoiding carrier variants or confirming that they can be unlocked; the same stock OS and firmware can still have different carrier unlock policy. ([Supported devices FAQ](https://grapheneos.org/faq#supported-devices), [web installer prerequisites](https://grapheneos.org/install/web#prerequisites))
- Some carrier SKUs require internet access while enabling OEM unlocking so stock Android can check the carrier lock status. An absent or disabled OEM-unlocking toggle is a stop condition for this install path. ([OEM-unlocking instructions](https://grapheneos.org/install/web#enabling-oem-unlocking))
- The official documentation does not provide a current Verizon model-number matrix. Treat Verizon/carrier-sold units as unverified until the exact unit exposes OEM unlocking and can be unlocked; GrapheneOS forum posts about Verizon variants are secondary, anecdotal reports, not a universal SKU rule. ([Official carrier warning](https://grapheneos.org/install/web#prerequisites), [forum: Verizon variant](https://discuss.grapheneos.org/d/1552-oem-unlocking-procedure-on-verizon-variant), [forum: Verizon Pixel](https://discuss.grapheneos.org/d/24254-no-way-to-use-my-verizon-pixel))
- Practical inference: SIM/network unlock status alone is not proof that bootloader unlocking is enabled, because GrapheneOS documents carrier configuration as separately controlling OEM/bootloader unlocking. Verify the OEM-unlocking setting before buying or relying on a device. ([Carrier guidance](https://grapheneos.org/install/web#prerequisites))

## Stock OS, firmware and rollback protection

- GrapheneOS recommends updating the stock OS before installation to provide recent firmware for USB and early flashing; its installer also flashes the latest firmware early in the process. The guides do not publish a separate minimum bootloader version table for current devices, so use the current official install flow and release rather than an old archive. ([Web prerequisites](https://grapheneos.org/install/web#prerequisites), [CLI prerequisites](https://grapheneos.org/install/cli#prerequisites), [official releases](https://grapheneos.org/releases))
- Pixel 6a (`bluejay`) has a specific stock-firmware prerequisite: the factory OS version does not support OEM unlocking correctly; update to the June 2022 release or later and then factory-reset before enabling OEM unlocking. ([Pixel 6a note](https://grapheneos.org/install/web#enabling-oem-unlocking))
- Verified boot rollback protection applies to firmware and OS. GrapheneOS documents firmware rollback indices in SoC fuses and OS rollback indices in the secure element, based on the security patch level; its future-device requirements also call out firmware and OS rollback protection. Avoid flashing an older factory image or firmware after a newer rollback index has been installed. ([Verified-boot explanation](https://grapheneos.org/install/web#verifying-installation), [hardware requirements](https://grapheneos.org/faq#which-devices-will-be-supported-in-the-future))
- The release directory's stable pointer is the current supported install target; the WebUSB installer resolves each device's `-stable` metadata before downloading its factory ZIP. This avoids selecting a stale build, but it does not make downgrades safe. ([Release service](https://releases.grapheneos.org/), [installer source](https://github.com/GrapheneOS/grapheneos.org/blob/81a53ee386cfa5c431e3e4c8088d7f9c581b5c69/static/js/web-install.js), [rollback protection](https://grapheneos.org/install/web#verifying-installation))

## Relocking and verified boot

- Relock only after the official factory-image operation has completed. The supported sequence flashes GrapheneOS and its verified-boot key before `fastboot flashing lock`; locking enables full verified boot and wipes user data again. ([Web flashing and locking](https://grapheneos.org/install/web#flashing-factory-images), [CLI locking](https://grapheneos.org/install/cli#locking-the-bootloader))
- Do not treat an unlocked bootloader as a completed install: it disables the full verified-boot protection that GrapheneOS expects. The GrapheneOS public key is stored in the secure element; the official guide says it can only be changed while unlocked, and unlocking also wipes the secure element. ([Verified-boot explanation](https://grapheneos.org/install/web#verifying-installation), [key hash and unlock behavior](https://grapheneos.org/install/web#verified-boot-key-hash))
- Unlock and relock both require on-device confirmation and erase data. ROMinit would need distinct typed-confirm gates for these destructive transitions and must not relock after a partial or failed flash. The wipe behavior and order are specified by the official guides. ([Unlocking](https://grapheneos.org/install/web#unlocking-the-bootloader), [locking](https://grapheneos.org/install/web#locking-the-bootloader))

## USB, browser and host setup

- A good USB cable and direct computer port matter: GrapheneOS identifies broken cables and hubs as the most common install problems and recommends avoiding hubs and virtual machines because USB passthrough can be unreliable. ([Web prerequisites](https://grapheneos.org/install/web#prerequisites), [CLI prerequisites](https://grapheneos.org/install/cli#prerequisites))
- On Linux, install the documented udev rules for non-root USB access. `fwupd` can claim fastboot devices and block the installer; the official workaround is to stop `fwupd.service` for the session. ([Web Linux instructions](https://grapheneos.org/install/web#flashing-as-non-root), [fwupd workaround](https://grapheneos.org/install/web#working-around-fwupd-bugs-on-linux-distributions))
- Windows 10/11 provide a generic fastboot driver for Pixel 4a (5G) and later; older Windows versions may need Google's Pixel USB driver through Windows Update or Device Manager. The Pixel Tablet must be disconnected from its charging/audio stand before USB installation. ([Windows driver instructions](https://grapheneos.org/install/web#connecting-the-device), [Pixel Tablet note](https://grapheneos.org/install/web#connecting-the-device))
- For WebUSB, use an up-to-date supported browser, avoid private/incognito mode because it can restrict the storage needed for the factory image, and disable Brave Shields because its storage quota can be too small. Android tablet users should disable browser desktop mode so the installer can request reconnection after reboots. ([Browser and storage prerequisites](https://grapheneos.org/install/web#prerequisites))
- The WebUSB guide calls for at least 2 GB free memory and 32 GB free storage. Its supported-browser list excludes Ubuntu's Snap Chromium build because WebUSB is broken there. ([Web prerequisites](https://grapheneos.org/install/web#prerequisites))

## Google Play, Play Integrity and banking apps

- GrapheneOS does not bundle Google Play. Users can optionally install its compatibility-layer version; Google Play then runs as an ordinary sandboxed app without special OS privileges and is scoped to the profile where installed. The project describes compatibility as near-complete, while noting that a small amount of privileged functionality is unavailable. ([Features: Sandboxed Google Play](https://grapheneos.org/features#sandboxed-google-play))
- Sandboxed Google Play can resolve apps that require Play services, but it does not guarantee that every app will accept GrapheneOS. GrapheneOS says apps using Play Integrity can support it by checking standard hardware attestation and allowing official GrapheneOS signing keys; the official compatibility guide also maintains a changing list of apps that block GrapheneOS through Play Integrity. ([Attestation compatibility guide](https://grapheneos.org/articles/attestation-compatibility-guide), [sandbox behavior](https://grapheneos.org/features#sandboxed-google-play))
- Banking and payment compatibility is app- and region-specific; do not promise it for the whole category. The official compatibility guide lists examples including PhonePe and mada Pay, but its list is time-sensitive and does not certify every bank. A ROMinit `banking_apps` rating therefore needs an app-specific source or an explicit test; otherwise leave it unknown/untested. ([Current app compatibility list](https://grapheneos.org/articles/attestation-compatibility-guide))
