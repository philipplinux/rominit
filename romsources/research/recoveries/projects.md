# Android recovery project evidence

Snapshot research date: 2026-10-16. This describes the projects' public catalogs and source activity, not whether a recovery image boots or is safe for a particular phone. A device page, a source tree, and a downloadable build are separate evidence.

## OrangeFox

OrangeFox is an active custom recovery project with a public download catalog. Its official download site points users to the new project homepage and exposes a machine-readable API: `GET https://api.orangefox.download/v3/devices` returned 162 device records at this snapshot, with `supported`, codename aliases, model text, a device ID, and a device URL. The pagination envelope reported `count: 162` and `has_more: false`. The stable machine key for following a device is its API `id`, not a guessed device slug. [Download site](https://orangefox.download/), [API device feed](https://api.orangefox.download/v3/devices), [project home](https://orangefox.tech/).

Per-device releases are available at `GET https://api.orangefox.download/v3/releases?device_id=<id>`. The response includes filenames, version/type, build timestamp, file size, mirrors, and MD5 for the ZIP and (where present) recovery image. The laurel_sprout sample returns an archived R10.0 release from 2019, one mirror, and MD5 values; this is useful evidence of what the API provides, not evidence that an old image supports a current firmware. No SHA-256 field appeared in that response. [Sample release API response source](https://api.orangefox.download/v3/releases?device_id=5e59825a77c93477b29eaea4).

**Interpretation limits:** `supported: true` is the server's catalog flag. It does not prove a recent build, current maintainer, successful boot, or compatibility with a particular firmware / partition layout. The catalog may contain old or archived records. Treat release metadata and current device installation guidance as separate checks. Prefer SHA-256 when independently available; MD5 is only an upstream integrity hint, not a modern authenticity guarantee.

## PitchBlack Recovery Project (PBRP)

PBRP remains present and has recent distribution activity. Its current device site has 135 per-device pages in the `PitchBlackRecoveryDevices/PitchBlackRecoveryDevices.github.io` `pb` branch tree (135 `_oem/*.md` pages at snapshot). Device pages expose a status, maintainer, and device-tree link; for example the lavender page says **Official**, names PBRP Team, and links its device tree. The page's build list is dynamically loaded, so the scraped page does not itself provide the current filename or checksum. [Current PBRP device index source tree](https://github.com/PitchBlackRecoveryDevices/PitchBlackRecoveryDevices.github.io/tree/pb/_oem), [lavender device page](https://pitchblackrecoverydevices.github.io/lavender/).

PBRP distributes device directories through [SourceForge](https://sourceforge.net/projects/pbrp/files/). At snapshot time its root showed directories modified as recently as 2026-01-31 (for example X6882 and X6881) and several late-2025 folders. This supports ongoing distribution activity, but a directory timestamp does not establish a build date for every device. An older official site data file, [`_data/devices.json`](https://raw.githubusercontent.com/PitchBlackRecoveryProject/PitchBlackRecoveryProject.github.io/master/_data/devices.json), maps device codenames to marketing names, maintainers, and release identifiers; it is useful historical metadata and is not the live build feed. Its compact `latest_release` values are retained as source strings, not normalized into dates.

PBRP page instructions distinguish installing its ZIP from an already installed recovery (copy ZIP to device storage, boot the existing recovery, flash, then reboot back to recovery to verify) and link device-specific tree/install details. The pages warn users to follow device-specific instructions. Do not infer that every device supports fastboot flashing or that a recovery ZIP can be installed from Android. [PBRP lavender install instructions](https://pitchblackrecoverydevices.github.io/lavender/).

**Interpretation limits:** PBRP has both an older release metadata file and a newer per-device site; fields can disagree or be absent. The current site status `Current`/`Official` is a project label, not independent proof of recent artifacts. SourceForge folder activity is project distribution evidence, not a per-device freshness guarantee. The observed page did not expose SHA-256/MD5 for its dynamically loaded builds; obtain the actual artifact and a trusted checksum before pinning a release.

## SkyHawk Recovery Project (SHRP)

SHRP is a TWRP-based recovery project with official website and GitHub device sources. The public device page describes an application process for maintainership, and the pinned `SHRP-Devices/device_data` repository calls its contents “Essential data of official devices.” Its raw [`deviceData.json`](https://raw.githubusercontent.com/SHRP-Devices/device_data/master/deviceData.json) contained 107 JSON objects (106 device rows plus a Dummy placeholder) at snapshot: brand, model, codename, maintainer, version, build number, download URL, and an MD5 field. Many records have empty build number / MD5 and point `latestBuild` only to a directory, so the field's presence must not be confused with an actual artifact hash. The companion [`devices.raw`](https://raw.githubusercontent.com/SHRP-Devices/device_data/master/devices.raw) lists tree codenames separately; the inventory labels codenames found only there as **device tree only**, not as a supported/released device.

The GitHub organization describes itself as the place for SHRP device trees and links to the device page. Its repo activity is mixed: many trees have older update timestamps, while some remain recently changed (for example `device_TECNO_CD6` was updated in March 2026). This is evidence of uneven source activity, not enough to call the whole project dead or to claim that a current binary exists for every tree. [SHRP devices organization](https://github.com/SHRP-Devices), [device_data repository](https://github.com/SHRP-Devices/device_data), [official devices page](https://skyhawkrecovery.github.io/Devices.html).

SHRP build downloads historically use SourceForge device folders. The `laurel_sprout` folder now identifies a separate **SHRP Reborn** project, which should not be silently treated as the original SHRP's current artifact feed. [SHRP laurel_sprout folder](https://sourceforge.net/projects/shrp/files/laurel_sprout/), [SHRP Reborn project](https://sourceforge.net/projects/shrp-reborn/).

**Interpretation limits:** `deviceData.json` is the web app's official-device feed, not proof of a currently maintained build. `devices.raw` records codenames, not release status. The checksum values are MD5 and frequently absent. A SourceForge folder may now point to a successor/fork. Verify project identity, exact device variant, artifact date, install route, and a stronger digest where available.

## Maintained and older alternatives

- **TWRP** remains the broad baseline to check. TeamWin publishes official supported-device pages and per-device downloads; its official catalog is distinct from unofficial builds hosted by individual maintainers. The device page may describe `fastboot boot` vs installing a recovery partition, and those instructions are model-specific. [Official device index](https://twrp.me/Devices/), [official download host](https://dl.twrp.me/).
- **LineageOS Recovery** is the recovery delivered for devices supported by LineageOS. Availability follows each device's official LineageOS support and release downloads; it is not a universal standalone recovery catalog. The recovery image can be part of device-specific install documentation, and flashing another ROM's recovery may break the supported update flow. [LineageOS install guide](https://wiki.lineageos.org/installation/), [downloads](https://download.lineageos.org/).
- **OrangeFox** and **PBRP** have active official catalogs / distribution evidence as described above, but per-device status and artifact recency still need checking.
- **SHRP** has an official device metadata feed and continuing repository activity in at least some trees, but its build metadata is incomplete and some SourceForge paths resolve to SHRP Reborn. Classify support per device and per artifact; do not label the whole project dead based on older repository dates.
- **SHRP Reborn** is a separate successor/fork identity visible on SourceForge. It can be researched as its own project if a device folder points there; do not merge those downloads into SHRP's original catalog. [Project page](https://sourceforge.net/projects/shrp-reborn/).

Across all projects, distinguish **official project device listing**, **device tree exists**, **artifact is available**, and **artifact has a usable cryptographic digest**. A downloaded recovery is device-specific and flashing can overwrite recovery/boot-related partitions or prevent normal boot. Require exact model/variant and device instructions; keep recovery installation separate from ROM installation; retain an unmodified backup/recovery route where available. Never infer safe installation commands from another device that merely shares a codename family or chipset.

## Resumed research: additional project and historical projects

**SHRP Reborn — source-active, binary freshness unresolved.** Its [official organization](https://github.com/SHRP-Reborn) describes a continuation of SHRP. The [captured repositories API](https://api.github.com/orgs/SHRP-Reborn/repos?per_page=100) lists 18 repositories; recovery/vendor/site work was pushed in May 2026. Its [pinned device feed](https://raw.githubusercontent.com/SHRP-Reborn/device_data/d046ee3c216432c76b281aaae196b893fa97b6eb/deviceData.json) contains six real device records plus a Dummy placeholder: X00T, phoenix, surya, munch, mi439, x1s. The matching [tree-name roster](https://raw.githubusercontent.com/SHRP-Reborn/device_data/d046ee3c216432c76b281aaae196b893fa97b6eb/devices.raw) agrees. The org additionally contains op5daal1 and nabu trees, retained as tree-only. Source pushes establish ongoing source work, not new builds: the feed's named ZIPs are from 2023, with no sizes or SHA-256 values. X00T's `baseURL` uses shrp-reborn but `latestBuild` still uses shrp; preserve this disagreement. No tested-device codename is in this Reborn feed; historical laurel_sprout downloads pointing to a successor must not become an invented official Reborn device row.

**PhilZ Touch — dead/discontinued.** The [device maintainer's recovery page](https://andi34.github.io/recoveries_tab2.html) explicitly calls PhilZ Touch discontinued and recommends TWRP. Its [upstream README](https://raw.githubusercontent.com/PhilZ-cwm6/philz_touch_cwm6/master/README.md) identifies it as ClockworkMod 6 based. This is historical research, not a source of maintained catalog releases; no global historical roster was fetched.

**ClockworkMod Recovery — legacy; no maintained recovery release source verified.** PhilZ's upstream identifies its CWM lineage. A guessed GitHub `ClockworkMod/ClockworkMod-Recovery` API path returned 404; that failure alone does not prove a project dead. No current official recovery roster or binaries were established, so do not import it as maintained. Its present general website/search result is not evidence of recovery development. Other private/unofficial forks were not exhaustively enumerated.

### Raw-source accounting

SHRP's raw JSON has 107 objects: 106 device rows and one `{brand: Dummy}` placeholder. Two device rows share `crownlte` but name different phones (Note 9 vs Note 10+ 5G, with `crownlte/` vs `d2x/` download folders). Both are preserved with distinct `device_key` values; this is an upstream mapping conflict, not universal compatibility. Another 25 tree-only rows bring SHRP to 131 source entries. PBRP has 135 site pages plus eight unmatched tree-only entries (143 total). Their model and maintainer strings remain source declarations, not verified maintainer identities. [SHRP raw data](https://raw.githubusercontent.com/SHRP-Devices/device_data/master/deviceData.json), [PBRP page tree](https://api.github.com/repos/PitchBlackRecoveryDevices/PitchBlackRecoveryDevices.github.io/git/trees/pb?recursive=1)
