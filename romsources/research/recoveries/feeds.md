# Recovery inventory feeds

Snapshot date: 2026-10-16. These are polite, publicly exposed catalog sources for ROMinit research. The available `collect.py` client identifies itself as `ROMinit-research/1.0`, checks each host's `robots.txt`, waits at least one second between uncached requests, caches response bytes, and stops further requests to a host after 401/403/429. This document records candidate feeds and their limits; these are not a promise that the endpoints are stable APIs.

| Project | Feed | Machine-readable fields | Coverage / caveat |
|---|---|---|---|
| OrangeFox | [`GET /v3/devices`](https://api.orangefox.download/v3/devices) | Device ID, codename aliases, model labels, `supported`, featured/version label, device URL | Snapshot returned 162 entries, `count: 162`, `has_more: false`. `supported` is a catalog flag, not a build-freshness claim. |
| OrangeFox | [`GET /v3/releases?device_id=…`](https://api.orangefox.download/v3/releases?device_id=5e59825a77c93477b29eaea4) | Filename, variant, version/type, Unix timestamp, size, MD5 for ZIP and optional image, URL/mirrors, archived flag | Requires device ID. Sample contained one archived 2019 release. MD5 is not SHA-256; do not assume a device has a current release because it has a historical response. |
| PBRP | [Current site GitHub tree](https://api.github.com/repos/PitchBlackRecoveryDevices/PitchBlackRecoveryDevices.github.io/git/trees/pb?recursive=1) | Page paths under `_oem/`; per-page frontmatter includes title, codename, support status, maintainer, device tree | 135 device pages at snapshot; tree is a roster, not live binary metadata. Use exact page to check official status / currentness labels. |
| PBRP | [SourceForge root](https://sourceforge.net/projects/pbrp/files/) | Device folders and their modified date | Root listing showed directories modified through 2026-01-31. Dates are directory-level and not per-artifact checksum evidence. Individual folders can expose filenames and file digests. |
| PBRP | [Legacy `devices.json`](https://raw.githubusercontent.com/PitchBlackRecoveryProject/PitchBlackRecoveryProject.github.io/master/_data/devices.json) | OEM → codename → model name, maintainer, compact `latest_release` string | Historical static release metadata. Preserve source string; do not parse to date without validating its format and meaning. |
| SHRP | [`deviceData.json`](https://raw.githubusercontent.com/SHRP-Devices/device_data/master/deviceData.json) | Brand, model, codename, maintainer, version, build number, latest-build URL, MD5 | 107 JSON objects (106 device rows plus a Dummy placeholder). Many build numbers and MD5 values are blank; many `latestBuild` values identify a folder, not a file. The repository says it contains essential data for official devices. |
| SHRP | [`devices.raw`](https://raw.githubusercontent.com/SHRP-Devices/device_data/master/devices.raw) | Comma-separated device codenames | Tree roster only. A codename absent from `deviceData.json` must remain “device tree only” absent artifact evidence. |
| SHRP | [GitHub organization repos API](https://api.github.com/orgs/SHRP-Devices/repos?per_page=100) | Repo names, descriptions, push timestamps, default branches | 100 repos across first and second pages in the observed query; use pagination. `pushed_at` is source repository activity, never a build date. |
| PBRP | [GitHub organization repos API](https://api.github.com/orgs/PitchBlackRecoveryDevices/repos?per_page=100) | Repo names, descriptions, push timestamps, default branches | First page returned the org's public repos; the second page was empty at snapshot. Repo/tree presence is not a download or maintenance guarantee. |

## Suggested collection and classification

1. Fetch OrangeFox's devices endpoint once; follow release queries only for candidate device IDs. Preserve the API ID and response timestamp. Do not paginate unless `has_more` says more data exists.
2. For PBRP, use the current device page/frontmatter for project status, then inspect the linked device folder for actual files. Keep legacy release tags in their own raw field. PBRP's build list loads dynamically, so a static page scrape can omit it.
3. For SHRP, join `deviceData.json` and `devices.raw` by exact `codeName`; classify only the unmatched tree names as device-tree-only. Preserve raw `buildNo`, `currentVersion`, URL and MD5; blank means unknown, not “no release.”
4. For all projects, record artifact URL, filename, observed date, exact supported model variants, install instructions, and SHA-256 when the upstream project supplies or independently publishes it. Do not upgrade MD5 to SHA-256 or convert a repository `pushed_at` timestamp into a release date.

The normalized point-in-time PBRP/SHRP device records are in [`other-devices.json`](other-devices.json). Its SHRP source-feed rows and tree-only rows intentionally remain distinct. PBRP status values are copied from current official site page metadata where available; `last_build_date` remains null because the source data did not provide a validated per-page build date.

## TWRP, LineageOS and SHRP Reborn

- **TWRP roster:** [`search.json`](https://twrp.me/search.json) is a compact searchable roster; [website source](https://github.com/TeamWin/twrpme) frontmatter is richer (model, maintainer, tree, install includes). The saved pinned archive is the bulk source used here. [`feed.xml`](https://twrp.me/feed.xml) is a project-news RSS feed, confirmed by the pinned source's [feed template](https://github.com/TeamWin/twrpme/blob/3fb09c958d84d6ee86908a2b7ca069171969c64b/feed.xml); it is not a per-device binary release feed. Poll only shortlisted [download indexes](https://dl.twrp.me/hero2lte/) for new filenames. No complete release sitemap was found. GitHub commits and Jenkins source/build activity are hints, not artifact pins.
- **LineageOS:** [`/api/v2/oems`](https://download.lineageos.org/api/v2/oems) supplies the current target catalog. [`/api/v2/devices/laurel_sprout/builds`](https://download.lineageos.org/api/v2/devices/laurel_sprout/builds) supplies dated builds and associated image metadata. Select `boot.img`, `recovery.img`, or other images according to that device's [install guide](https://wiki.lineageos.org/devices/laurel_sprout/install/); a ROM ZIP is not the recovery. Prefer these build APIs over treating GitHub source releases as recovery releases. Poll a target only when it is relevant; the earlier run's all-target crawl is recorded in README.
- **SHRP Reborn:** the complete captured [device metadata](https://raw.githubusercontent.com/SHRP-Reborn/device_data/d046ee3c216432c76b281aaae196b893fa97b6eb/deviceData.json) and [tree-name list](https://raw.githubusercontent.com/SHRP-Reborn/device_data/d046ee3c216432c76b281aaae196b893fa97b6eb/devices.raw) contain six devices. The [organization API](https://api.github.com/orgs/SHRP-Reborn/repos?per_page=100) adds two source-tree-only targets. Poll repository changes to trigger a bounded re-read, then verify the actual SourceForge artifact. The static feed has old filename dates and no SHA-256 values; May 2026 source pushes do not refresh those binaries.

No working project-specific RSS/Atom binary feed was verified for OrangeFox, PBRP, SHRP or SHRP Reborn. GitHub's generic commits Atom endpoints and SourceForge RSS endpoints are candidates, not exercised feeds in this snapshot. Avoid treating absence of a verified feed as proof no feed exists.
