# Recovery and install pitfalls

Snapshot researched 2026-10-16. Use each device's live instructions and exact model/build. These are research notes; they do not authorize a flash.

## Device-specific traps

- **`hero2lte` means Exynos Galaxy S7 edge variants in the current Lineage guide.** It lists only SM-G935F/FD/S/K/L/W8. Do not treat every Galaxy S7 edge, particularly Snapdragon variants, as interchangeable. Its route is Download Mode → `samloader-rs` writes `RECOVERY` with `--no-reboot` → manually enter recovery. Then Format Data and separately wipe System and Cache before sideloading. [LineageOS hero2lte guide](https://wiki.lineageos.org/devices/hero2lte/install/)
- **`starlte` and `star2lte` require Android 10 firmware.** The LineageOS guides warn of install failure, crashes, or permanent damage if firmware is wrong. S9 model allowlist is SM-G960F/FD/N; S9+ is SM-G965F/FD/N. Do not infer the firmware requirement from One UI version; the guide specifies Android version. [S9 guide](https://wiki.lineageos.org/devices/starlte/install/) [S9+ guide](https://wiki.lineageos.org/devices/star2lte/install/)
- **Samsung custom recovery can be lost if the phone boots normally.** LineageOS instructs `--no-reboot` then immediate manual recovery entry. Team Win also warns about automatic stock recovery replacement. The recipe must stop after flashing and clearly hand off the key sequence; an automatic normal reboot is the wrong next step. [LineageOS starlte guide](https://wiki.lineageos.org/devices/starlte/install/) [TWRP starlte](https://twrp.me/samsung/samsunggalaxys9.html)
- **S9 TWRP and dm-verity:** Team Win says `starlte` uses dm-verity; allowing system modifications may prevent boot with the stock kernel unless dm-verity is disabled. This is a warning against generic “mount system writable” instructions. It is specific evidence for `starlte`; verify `star2lte` separately before applying the same statement. [TWRP starlte](https://twrp.me/samsung/samsunggalaxys9.html)
- **`laurel_sprout` recovery is the boot image.** Current Lineage instructions flash `boot.img` to `boot`, immediately enter recovery, and warn not to start the existing OS because it overwrites the recovery. Firmware prerequisite is stock Android 11. Exact models are M1906F9SH/SI. A generic recipe that flashes partition `recovery` is incorrect here. [LineageOS laurel_sprout guide](https://wiki.lineageos.org/devices/laurel_sprout/install/)
- **`sailfish` needs a capacity-specific repartition step.** The Pixel guide supplies separate 32 GB and 128 GB repartition ZIPs, then requires rebooting back into recovery before normal installation. Selecting the wrong ZIP or omitting the second recovery boot breaks the documented sequence. Exact capacity must be an explicit human choice and typed confirmation. [LineageOS sailfish guide](https://wiki.lineageos.org/devices/sailfish/install/)
- **Format Data erases internal storage.** The S9/S9+ and Mi A3 guides explicitly say formatting removes encryption and deletes internal files; Pixel does too. Make backup and data loss visible before any destructive stage. [starlte](https://wiki.lineageos.org/devices/starlte/install/) [laurel_sprout](https://wiki.lineageos.org/devices/laurel_sprout/install/) [sailfish](https://wiki.lineageos.org/devices/sailfish/install/)

## Recovery names do not establish compatibility

- Official TWRP pages exist for the Exynos S7 edge/S9/S9+, Mi A3 has its own A/B install page (see fit notes), and TWRP has a separate Pixel `sailfish` page. Match recovery artifact to exact codename and install method. Samsung Team Win downloads include `.tar` packages for Odin; ROMinit's `odin` recipe accepts a blob-to-partition step and does not itself establish that it understands an Odin archive. [TWRP hero2lte](https://twrp.me/samsung/samsunggalaxys7edge.html) [TWRP starlte](https://twrp.me/samsung/samsunggalaxys9.html) [TWRP star2lte](https://twrp.me/samsung/samsunggalaxys9plus.html) [TWRP sailfish](https://twrp.me/google/googlepixel.html)
- OrangeFox's `laurel_sprout` download page reports R10.0 Stable dated 2019-10-15. That is a historic build listing, not current ROM compatibility evidence. [OrangeFox laurel_sprout](https://orangefox.download/device/laurel_sprout)
- PBRP's project description alone does not establish per-device builds. Verify a maintainer's exact device page and published artifact before listing it. [PBRP](https://pitchblackrecovery.com/)
- SHRP's SourceForge page marks the project abandoned. A historical official `laurel_sprout` XDA thread does not establish current support, and does not transfer to other devices. [SHRP files](https://sourceforge.net/projects/shrp/files/) [laurel_sprout thread](https://xdaforums.com/t/recovery-official-laurel_sprout-skyhawk-recovery-project-v2-3-1-08-06.4069883/)

## Current engine boundary

ROMinit `fastboot` is not a complete guide runner: it flashes/erases physical partitions, changes A/B active slot, and reboots, but has no temporary `boot` command, recovery-key navigation, dynamic-partition handling, or menu action. `odin` writes explicit partition payloads after PIT name/size checks, but cannot call `samloader-rs`, boot to recovery, or package/extract `.tar.md5`. `twrp-sideload` transports ZIPs but cannot format data or make recovery-menu choices. `twrp-dd` writes raw images and formats ext4; it is not a recovery ZIP installer. Relevant code: [`fastboot.js`](../../../src/recipes/fastboot.js), [`odin.js`](../../../src/recipes/odin.js), [`twrp-sideload.js`](../../../src/recipes/twrp-sideload.js), [`twrp-dd.js`](../../../src/recipes/twrp-dd.js).

The official LineageOS Samsung route now uses `samloader-rs`, whereas ROMinit's Download Mode code is named `odin`. Treat their equivalence as unproven. README says browser flashing has not yet been tested on real hardware. Keep ROM status/requirements and stage warnings honest until each transport, artifact, and boot result is verified.

## Encryption, Android branches and A/B scope

TWRP's [3.7.0 release notes](https://github.com/TeamWin/twrpme/blob/3fb09c958d84d6ee86908a2b7ca069171969c64b/_posts/2022-10-10-3.7.0-released.markdown) explicitly separate Android 9, 11 and 12.1 branches; Android 12 encryption support is under the 12.1 branch. Thus a numeric `3.7.0` version alone cannot establish FBE decryption support for a particular phone/ROM. PIN/keymaster/vendor dependencies and the exact image branch need per-device confirmation. No decryption was tested here. [3.6.0 notes](https://github.com/TeamWin/twrpme/blob/3fb09c958d84d6ee86908a2b7ca069171969c64b/_posts/2021-11-28-twrp-3.6.0-released.markdown) also distinguish encryption changes, virtual A/B work and recovery-as-boot repacking.

TWRP Mi A3's [A/B install include](https://github.com/TeamWin/twrpme/blob/3fb09c958d84d6ee86908a2b7ca069171969c64b/_includes/fastbootabinstall.html) warns against permanent whole-image flashing in place of temporary boot/ramdisk installation. Pixel's [device instructions](https://twrp.me/google/googlepixel.html) install the ZIP to both boot slots. These do not authorize switching an arbitrary active slot or applying the same sequence to Lineage Recovery. Slot state and firmware/ROM pairing remain explicit device requirements.

**AVB/vbmeta/vendor_boot remain device-specific open checks.** The saved S9 dm-verity warning is not proof every target requires an AVB-disable flag, blank vbmeta or vendor_boot write. None of the five captured install routes establishes a generic vendor_boot procedure. No vbmeta-disabling command or vendor_boot recipe is proposed without an exact upstream guide. Recovery-in-boot and vendor_boot must remain separate catalog partition targets; the current fastboot engine has no AVB-disable flags. See the linked target guides above and local `src/recipes/fastboot.js`.
