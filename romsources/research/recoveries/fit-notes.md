# Recovery research fit notes

Research snapshot: 2026-10-16. This is research input, not a vetted catalog entry or a tested install. Recovery builds and LineageOS instructions change; recheck the linked device page and exact build before pinning files. Never apply these instructions to a phone without its owner's explicit go-ahead and the device-specific typed confirmation.

## Install routes found

| Device | Official LineageOS install route | Recovery / firmware constraints |
|---|---|---|
| Samsung Galaxy S7 edge Exynos (`hero2lte`) | Enable OEM unlock; use Download Mode and `samloader-rs` to flash custom recovery to `RECOVERY` with `--no-reboot`; enter recovery with Vol Up + Home + Power; format data, wipe system/cache, then ADB sideload the ROM ZIP. | Exact listed models: SM-G935F/FD/S/K/L/W8. The current guide links TWRP. Current official guide does not list a prerequisite Android firmware baseline. [LineageOS install guide](https://wiki.lineageos.org/devices/hero2lte/install/) |
| Samsung Galaxy S9 Exynos (`starlte`) | Download Mode + `samloader-rs`; flash recovery to `RECOVERY`, no reboot; manually enter recovery with Vol Up + Bixby + Power; Factory Reset → Format data/factory reset; sideload ROM and any add-ons in order. | Exact listed models: SM-G960F, G960F/DS, G960N. Requires stock Android 10 firmware first. [LineageOS install guide](https://wiki.lineageos.org/devices/starlte/install/) |
| Samsung Galaxy S9+ Exynos (`star2lte`) | Same Download Mode / `samloader-rs` recovery flash and manual recovery entry; format data; ADB sideload ROM and add-ons. | Exact listed models: SM-G965F, G965F/DS, G965N. Requires stock Android 10 firmware first. [LineageOS install guide](https://wiki.lineageos.org/devices/star2lte/install/) |
| Xiaomi Mi A3 (`laurel_sprout`) | Fastboot unlock (wipes data); flash Lineage Recovery `boot.img` to `boot`; boot directly to recovery (do not start existing OS); format data; ADB sideload ROM and add-ons. | Exact models M1906F9SH / M1906F9SI. Stock Android 11 firmware prerequisite. Recovery occupies `boot`, not a separate `recovery` partition. [LineageOS install guide](https://wiki.lineageos.org/devices/laurel_sprout/install/) |
| Google Pixel, first generation (`sailfish`) | Fastboot unlock; flash Lineage Recovery `boot.img` to `boot`; enter recovery; on 32 GB or 128 GB variants, sideload the matching repartition ZIP and reboot recovery; format data; sideload ROM/add-ons. | Storage-size-specific destructive repartition is part of the published install route. [LineageOS install guide](https://wiki.lineageos.org/devices/sailfish/install/) |

Samsung guides require checking the exact model suffix; the listed Exynos models do not establish Snapdragon compatibility. Their current recovery flashing route is `samloader-rs`, not Android fastboot. They also say root is not needed. S9 and S9+ explicitly require Android 10 stock firmware; “Android version” is the requirement, not Samsung's vendor skin version. [S9 guide](https://wiki.lineageos.org/devices/starlte/install/) [S9+ guide](https://wiki.lineageos.org/devices/star2lte/install/)

## Recovery project fit

- **TWRP:** Official Team Win pages exist for `hero2lte` (S7 edge Exynos), `starlte` (S9 Exynos), `star2lte` (S9+ Exynos), `laurel_sprout` (Mi A3), and `sailfish` (Pixel). The S9 page explicitly warns that the device uses dm-verity and modifying system can prevent stock-kernel boot. Official device pages describe Samsung Odin `.tar` installation and Pixel-specific instructions; use the device page, not a generic recovery recipe. [hero2lte](https://twrp.me/samsung/samsunggalaxys7edge.html) [starlte](https://twrp.me/samsung/samsunggalaxys9.html) [star2lte](https://twrp.me/samsung/samsunggalaxys9plus.html) [sailfish](https://twrp.me/google/googlepixel.html)
- **TWRP download-link terms:** Team Win permits linking its HTML pages but disallows direct links to files. For ROMinit catalog entries, use the per-device HTML download page as `source` and omit `url`; let the user open that page and download the chosen artifact. The page warns that firmware changes can break compatibility and that a different device image generally will not work. [Team Win download page and terms](https://dl.twrp.me/hero2lte/)
- **OrangeFox:** The official download site has a `laurel_sprout` page, but its displayed last release is R10.0 Stable from 2019-10-15. Treat it as an old artifact lead, not evidence of current LineageOS compatibility. Searches for the three Samsung codenames did not yield official device pages; support remains unverified. [OrangeFox laurel_sprout page](https://orangefox.download/device/laurel_sprout)
- **PitchBlack Recovery (PBRP):** The project advertises a TWRP-based recovery, but the official project page does not verify a build for these five device codenames. Do not make a catalog recovery option until a maintainer-published device artifact and install instructions are found. [PBRP](https://pitchblackrecovery.com/)
- **SkyHawk Recovery (SHRP):** The project site says SHRP is a TWRP-derived recovery; its SourceForge files page marks the project abandoned. There is an XDA thread for an official `laurel_sprout` SHRP build, but that is device-specific and historical; no claim of current compatibility follows. The captured feed also lists the three Samsung targets; current artifacts remain unverified and Pixel is absent. [SHRP site](https://skyhawkrecovery.github.io/) [SHRP files](https://sourceforge.net/projects/shrp/files/) [laurel_sprout thread](https://xdaforums.com/t/recovery-official-laurel_sprout-skyhawk-recovery-project-v2-3-1-08-06.4069883/)

## ROMinit recipe fit and catalog implications

Current engines are `fastboot`, `odin`, `twrp-dd`, and `twrp-sideload` (plus stock-package `fastboot-tgz`). Source: [`src/catalog.js`](../../../src/catalog.js) and [`src/recipes/`](../../../src/recipes/).

- `fastboot` checks product, unlocked state, pinned hashes and physical partition size; it can flash/erase physical partitions, set active A/B slot, and reboot. It rejects logical partitions and has no `boot` (temporary boot), `flashall`, dynamic-partition/super, or recovery-menu operation. This supports an explicitly pinned `boot.img` → `boot` write where the device really maps recovery there (Mi A3, Pixel), but does not perform an automatic reboot-to-recovery or validate the recovery image's internal compatibility.
- `odin` takes explicit partition/blob writes and validates partition existence/size via PIT, then writes without reboot. It does not invoke `samloader-rs`, identify model (PIT names are only a layout proxy), package `.tar.md5`, switch to recovery, or perform the user-held key sequence. Official Lineage guides use `samloader-rs`; a TWRP `.tar` from a Team Win page is not automatically a valid raw-Blob input for this engine.
- `twrp-sideload` streams pinned ZIP files through the ADB sideload transport. It relies on recovery/updater validation and does not itself select Wipe/Format, reboot between ROM/add-on steps, interpret signature prompts, or check the resulting OS. Current recipes can represent a sequence of ZIPs, but cannot perform screen-only menu steps.
- `twrp-dd` is a destructive raw block writer from an ADB-capable TWRP. It verifies target identity through `ro.product.device`, checks block sizes/mounts, verifies image hashes and reads each write back; its vocabulary is only `write`, `mkfs_ext4`, and `reboot`. It cannot install Odin archives or issue fastboot/samloader commands.

Catalog shape already has device `models`, `detect`, `modes`, `unlock`, and `recovery`; ROM entries have `origin`, `status`, `vetting`, `rating`, `includes`, `kernel`, `base`, `released`, `support`, `slots`, `requirements`; stages carry `recipe`, `mode`, pinned `files`, ordered `steps`, `confirm`, and warning fields. Keep per-ROM steps/requirements in ROM JSON; do not encode flash knowledge in `site/app.js` (repository README / AGENTS policy).

Minimum catalog modeling for these routes:

1. Exact commercial model suffixes and codename must be separate matching facts. For Samsung, represent Download Mode and recovery/ADB; for Mi A3 and Pixel, represent fastboot and recovery/ADB. Recovery project is not equivalent to a ROM stage.
2. Put irreversible wipe/repartition intent in stage `warning` plus a unique human-typed `confirm`; spell out Android 10 or Android 11 firmware floor, Samsung model limitation, and Pixel storage-size branch in `requirements`.
3. Pin each actual artifact (source page, exact file name/size/SHA-256) and order recovery → manually enter recovery → wipe/format → ROM sideload → optional add-ons. Manual steps and model/storage choices must be exposed clearly because the engines cannot make them.
4. The `odin` recipe is only a candidate for a raw recovery image and PIT-checked target. Do not describe current browser flow as implementing official Samsung recovery installation until archive/container compatibility and a real supported transport are established. The repo README says no browser flash has been tested on real hardware.

Gaps to close before a flashable entry: authoritative current artifacts and hashes for each recovery/ROM; exact Samsung Download Mode USB method and support coverage of the browser's Odin implementation; correct firmware restoration path; explicit confirmation staging for data wipe, unlock, and Pixel repartition; exact recovery version compatibility with each ROM build; and end-to-end hardware validation. Do not imply that a successful file transfer is a booted/working ROM.

## Target corrections from the saved bulk sources

The complete captured TWRP roster **does** include [Mi A3](https://twrp.me/xiaomi/xiaomimia3.html), maintained in that source by Nikesh001. Its included [A/B install instructions](https://github.com/TeamWin/twrpme/blob/3fb09c958d84d6ee86908a2b7ca069171969c64b/_includes/fastbootabinstall.html) require temporary `fastboot boot`, then Flash Current TWRP or Install Recovery Ramdisk, and warn about boot-loop repair and accidental raw boot flashing. This differs from LineageOS's published whole-boot-image install route. ROMinit cannot substitute `fastboot flash boot` for the TWRP route.

The [Pixel TWRP source page](https://github.com/TeamWin/twrpme/blob/3fb09c958d84d6ee86908a2b7ca069171969c64b/_google/googlepixel.markdown) likewise requires temporarily booting an image then installing the ZIP to both boot slots; it warns that installation removes existing root. This is separate from the LineageOS Pixel recovery/repartition route above.

The [SHRP official metadata feed](https://raw.githubusercontent.com/SHRP-Devices/device_data/master/deviceData.json) lists hero2lte (2.3.2, Morogoku), starlte/star2lte (3.1, corsicanu), and laurel_sprout (3.1, HemantSachdeva). For hero2lte and Mi A3 it names old ZIPs and MD5s; for S9/S9+ it provides directories only. This establishes listing/maintainer declarations, while current binary availability, SHA-256 and installation compatibility remain unverified. Pixel is absent. PBRP's captured site/tree inventory contains none of the five exact target codenames. Absence from these captured lists does not rule out unofficial ports.
